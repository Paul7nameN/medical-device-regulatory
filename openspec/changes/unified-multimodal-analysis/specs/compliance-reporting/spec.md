## MODIFIED Requirements

### Requirement: Compliance report storage
The system SHALL persist generated compliance reports for devices and time periods, including multi-modal source information when applicable.

#### Scenario: Create compliance report
- **WHEN** a compliance report is generated for a device or fleet
- **THEN** a record is created in `compliance_reports` with report metadata, summary, and content reference

#### Scenario: Report period tracking
- **WHEN** a report covers a specific time range
- **THEN** `period_start` and `period_end` timestamps define the coverage window

#### Scenario: Device association
- **WHEN** a report is device-specific
- **THEN** `device_id` foreign key links to the associated device

### Requirement: Report summary and statistics
The `compliance_reports` table SHALL store summary statistics including violation counts by severity, regulation, and data source.

#### Scenario: Violation summary
- **WHEN** a report summarizes detected violations
- **THEN** `summary` JSON field contains counts by severity and reg_code

#### Scenario: Compliance score
- **WHEN** calculating compliance
- **THEN** `compliance_score` (numeric 0-100) represents the compliance percentage

#### Scenario: Report status
- **WHEN** tracking report generation lifecycle
- **THEN** `status` field tracks 'generating', 'completed', 'failed' states

#### Scenario: Multi-modal summary
- **WHEN** report is generated from multi-modal analysis
- **THEN** `summary` includes: correlated_findings_count, conflicting_findings_count, avg_correlation_confidence

### Requirement: Report content access
The `compliance_reports` table SHALL provide access to full report content including multi-modal evidence and correlations.

#### Scenario: Report path reference
- **WHEN** report is stored as a file
- **THEN** `report_path` field contains the file path or storage key

#### Scenario: Generated timestamp
- **WHEN** report generation completes
- **THEN** `generated_at` timestamp records completion time

#### Scenario: Generated by tracking
- **WHEN** report is generated by a user or system
- **THEN** `generated_by` field identifies the initiator

#### Scenario: Unified report data sources
- **WHEN** report includes findings from multiple modalities
- **THEN** each finding record includes `data_sources` array and `confidence` score from correlation engine

## ADDED Requirements

### Requirement: Multi-modal report enhancements
The system SHALL generate enhanced compliance reports with correlation insights and discrepancy tracking when analysis includes multiple modalities.

#### Scenario: Correlation insights section
- **WHEN** `config._correlation.correlated_findings` is not empty
- **THEN** report includes "Correlation Insights" section with narrative descriptions of multi-modal pattern matches

#### Scenario: Discrepancies section
- **WHEN** `config._correlation.conflicting_findings` is not empty
- **THEN** report includes "Discrepancies for Human Review" section highlighting log-chart conflicts

#### Scenario: Finding source indicators
- **WHEN** displaying any finding in report
- **THEN** visual indicators show which modalities contributed (log icon, chart icon, both)

#### Scenario: Confidence-based severity adjustment
- **WHEN** finding has multi-modal confirmation
- **THEN** confidence score > 0.9 may elevate suggested review priority
